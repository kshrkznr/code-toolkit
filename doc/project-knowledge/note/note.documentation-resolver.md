# The Resolver Emerged from Repeated Navigation

The Documentation Resolver was not designed in advance as a complete
documentation system.

As CTK's documents increased, both people and AI repeatedly had to infer which
document should be read next. The Resolver made that recurring judgment
explicit and reusable.

This is why the Resolver works naturally as question-based navigation:

```text
Current question
      ↓
Relevant document responsibility
      ↓
Next useful context
```

It does not require every document to be read, and it does not define one fixed
priority order. Reading guidance may still help in a particular situation—for
example, understanding an accepted responsibility before interpreting a
concrete practice—but that guidance remains contextual.

The reusable observation is loose:

> When people repeatedly infer the same navigation decision, making that
> decision visible may be more useful than prescribing a complete reading path.

This Note describes how CTK's documentation practice evolved. It does not add a
new responsibility to the Documentation Resolver.
