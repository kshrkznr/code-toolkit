# Knowledge as Shared Context

This Note records a loose observation from CTK collaboration.

It is not a documentation policy, an instruction for AI, or a claim that the
same effect will occur in every project.

## Observation

Knowledge documents were most useful when they provided common material for
judgment rather than prescribing the next action.

That material included:

- concepts and shared vocabulary
- current responsibilities and boundaries
- design rationale and observations
- examples of how the author interpreted the concepts

With that context available, a discussion could spend less time reconstructing
the project and more time considering the current question.

## Influence rather than instruction

Knowledge does not determine one correct proposal.

```text
Knowledge
    +
Current conversation
    +
User context
    ↓
Situation-specific judgment
```

The same Knowledge may support different conclusions when the task or user
context changes.

In that sense, Knowledge acts more like shared context or a gentle influence on
reasoning than a rulebook.

## Boundary

Current responsibilities should take priority over historical observations.
Notes, Experiments, and Author's Recipe contribute different kinds of context;
they do not all carry the same authority.

The observation also does not explain the internal behavior of an AI system.
It only records that shared project structure and vocabulary appeared to change
the quality of collaboration in this project.
